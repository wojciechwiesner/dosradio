# VibingDiary — 2026-11-05 — DOS Radio Plus Wave (v1.2.0)

## Context & Objectives
Orkiestracja wdrożenia pozostałych funkcji DOS Radio: duet podcasts (NotebookLM-PL),
personalizowane źródła wiadomości (RSS/keywords) oraz płatności Stripe (test mode).
Ograniczenie środowiskowe: host swap nasycony w 95% (29.2 GB / 30.7 GB) — twardy limit
maksymalnie 2 równoległych workerów.

## Architecture & Decisions
1. **Model orkiestracji**: 2 izolowane git worktrees (`wt/plus-core`, `wt/stripe-billing`)
   z pre-zaaplikowanym wspólnym baseline (`bbcab50`: kolumny `users.plan`, `users.plus_until`,
   tabela `news_preferences`, flaga `Access.plus`) oraz hookami montażu w `main.py`
   i `index.html`, co wyeliminowało jakiekolwiek kolizje w plikach współdzielonych.
2. **Failover harnessa**: Claude Code wyczerpał tygodniowy limit (reset 12am), Codex CLI
   miał wygasły token — automatyczny failover na OpenCode (v2.1.4 z modelem GLM-5.3 przez
   Borg LLM Proxy). Oba workery zrealizowały 100% zakresu w swoich drzewach roboczych.
3. **Stripe Test Mode**: pełna integracja z SDK `stripe`, plany 39 PLN (Plus) i 59 PLN
   (Plus+AI, B2B invoice billing). Brak zmiennych `STRIPE_SECRET_KEY` nie wywala aplikacji
   (graceful 503 na checkout z czytelnym JSON-em).
4. **NotebookLM-PL Duet Podcasts**: 2-głosowa rozmowa (Ania i Michał) generowana modelem
   `gemini-3.8-flash` per canon projektu, 2 odrębne głosy Gemini TTS, przeplecione muzyką
   ze stacji DOS Radio. Cache pod `data/podcasts/`.
5. **Personalized News**: parser RSS 2.0 i Atom z twardym 5s timeoutem na feed i pełną
   izolacją wyjątków — martwy feed usera nigdy nie blokuje globalnego cyklu cogodzinnego.
